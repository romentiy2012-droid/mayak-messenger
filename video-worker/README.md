# Обработка видеокружочков

Закрытый HTTP-обработчик для Edge Function `video`. Получает небольшое задание с временными ссылками на исходник и результат. Файлы скачивает и загружает напрямую в Supabase Storage; ключ service_role ему не нужен. Браузер к обработчику не обращается.

## Развёртывание

1. Создать отдельный проект Vercel с корнем `video-worker`, preset Container, регион Paris (`cdg1`), максимальная длительность не меньше 150 секунд. `Dockerfile.vercel` использует Node 24 и поддерживаемый Debian trixie; FFmpeg/FFprobe устанавливаются из репозитория Debian при сборке. Контейнер работает от непривилегированного пользователя. Официальное описание: https://vercel.com/docs/functions/runtimes/container .
2. В закрытых переменных production задать `SUPABASE_URL`, `PORT=8080` и случайный `MAYAK_VIDEO_KEY` не короче 32 символов. Ключ хранить как Sensitive, не в Git и не в браузерном `config.js`. Проверить текущий тариф и доступные лимиты до запуска; платные ресурсы требуют отдельного решения владельца. Container Runtime доступен на всех планах; цена VCR и условия хранения: https://vercel.com/docs/container-registry/limits-and-pricing . Рабочая команда использует Active Hobby; обновление тарифа и платёжные средства при развёртывании не добавлялись. Ограничения бесплатного плана могут приостанавливать обработку.
3. Проверить `GET https://<проект>.vercel.app/api/process` и отказ 401 на POST без ключа. Адрес и тот же ключ внести служебным соединением в единственную строку `mayak_private.video_config` (`singleton=true, worker_url, worker_key`). Схема закрыта от клиентов; секрет не выводить в журналы.
4. Развернуть `supabase/functions/video/index.ts` с `verify_jwt=false`: JWT проверяется через Auth API, членство и права — RPC. Доступ функции только с адреса GitHub Pages приложения. При смене домена обновить CORS.
5. Проверить преобразование в облаке, HTTP 200 для здоровья и 401 без ключа. Проверить полный путь загрузки, создания сообщения, чтения с другого устройства и удаления. Проверить реальные iPhone и Android. После настройки выставить `videoEnabled: true` в публичном `config.js` и опубликовать клиент 2.11.

В Vercel передаётся только эта папка с исходниками и lockfile. Локальные журналы, записи камеры, `node_modules`, `.env` и материалы участников не публикуются. Сборка требует Docker локально либо облачной сборки. `verify-runtime.js` при каждой сборке в облаке проверяет настоящую конвертацию синтетических WebM и MP4 системным FFmpeg. Каталог `api/` здесь не нужен: он создаст отдельную Node-функцию поверх контейнерного маршрута. HTTP-маршрут `/api/process` обслуживает `server.js` через `lib/handler.js`.

## Локальные проверки

`npm ci` и `npm test` устанавливают бинарные пакеты только для синтетических тестов. Эти старые тестовые бинарники не входят в production: там `npm ci --omit=dev` и системные `/usr/bin/ffmpeg`, `/usr/bin/ffprobe`. Для проверки с актуальными локальными бинарниками задайте `FFMPEG_PATH` и `FFPROBE_PATH`. `npm start` запускает HTTP-сервер на `PORT` (по умолчанию 8080).

Лимиты: исходник 16 МБ и до 4096 точек по стороне; запись до минуты; обработка до 90 секунд; результат 8 МБ, 480 × 480, 30 кадров/с, H.264 Baseline level 3.1 и AAC-LC mono 48 kHz. Входные сетевые протоколы FFmpeg запрещены, принимаются только файловые MP4/MOV/WebM. Недостающие видео или звук дают понятную ошибку. Выход повторно проверяется FFprobe. Временная папка каждой обработки удаляется в `finally`.

Полный диапазон камеры (`pc`, при декодировании `yuvj420p`) реально переводится в limited через `scale:out_range=tv` и выходные `-color_range tv -pix_fmt yuv420p`. Одной смены тега недостаточно. `verify-runtime.js` проверяет full-range источник на облачном FFmpeg, подтверждает совместимый выход и декодирует кадр; в той же среде прежний код воспроизвёл отказ именно на этом случае. При провале проверки в журнал попадают только codec, pixel format, range, размеры, длительность и размер файла; адреса, токены и кадры не логируются.

Задания имеют одноразовую попытку-токен. Завершение сверяет токен, состояние, параметры и наличие результата, создаёт сообщение атомарно. Устаревший ответ не заменяет новое задание. При потерянном ответе успешной транзакции уже опубликованный файл сохраняется. Отложенная очистка потерянных исходников/результатов пока не реализована; следить за объёмом Storage.
