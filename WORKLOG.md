# Версия 2.3.0: черновики, сброс пароля, повтор уведомлений, модули — 16 ноября 2026

Владелец принёс четыре замечания со стороны и велел сделать все «под ключ».

- **Черновики.** Недописанный текст и выбранный ответ сохраняются на устройстве (отдельно для каждого участника) и переживают перезапуск. Сохраняется и номер отправки: если сообщение ушло, а ответ не дошёл, повтор не создаёт дубль. При выходе из аккаунта черновик стирается.
- **Вход и забытый пароль.** Выбран один сценарий: вход по имени (технический адрес u_…@mayak.app), без подтверждения почты. Владелец в «Участники, имя и пароли» нажимает «Сбросить пароль» и отправляет участнику одноразовую ссылку на сутки; участник задаёт новый пароль и сразу входит. При регистрации почта вместо имени не принимается; в поле входа помещается и почта (у одного старого аккаунта вход по настоящей почте). README переписан под этот сценарий. Пароль владельца меняется в Supabase (Authentication → Users).
- **Уведомления.** Сообщение помечается отправленным только после ответа push-сервисов. Функция сама повторяет отправку при временном сбое (три попытки), база раз в минуту (pg_cron, задача mayak-push-retry) заново вызывает функцию — до шести раз за 15 минут и только по недоставленным устройствам. Ошибка ключа повтором не считается.
- **Код.** app.js разделён на модули в js/ (core, session, messages, composer, actions, dialogs, push, viewport, sound), без сборки. Лента обновляется по частям: строка пересоздаётся, только если в ней что-то изменилось.
- Заодно исправлено отложенное: на экране входа теперь «Облако на связи», а не «Нет соединения» (проверка связи больше не читает закрытую таблицу).
- База (cfzzxkmctwrclhphqslr): миграция `reliability` (supabase/migrations/202611160004_reliability.sql) — таблица кодов сброса, RPC mayak_reset_issue/check/done, колонки push_tries/push_at/push_pending, mayak_push_result, расширение pg_cron и две задачи. Функции: `push` версия 3, новая `reset` версия 1 (verify_jwt=false).
- Проверено: npm test 8/8 (база и обе функции на заглушках); в Chromium с размерами iPhone и на широком экране на подставном сервере — черновик после перезагрузки и после сбоя отправки, ссылка сброса у владельца, форма нового пароля, вход, регистрация, выход, частичное обновление ленты и все прежние сценарии, ошибок в консоли нет; на рабочем сервере — функция reset отклоняет неверный и неизвестный код и отвечает на CORS, push отвечает, посторонний не может вызвать RPC сброса, задачи cron активны.
