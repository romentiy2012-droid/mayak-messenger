# Маяк

Закрытый общий PWA-чат: интерфейс на GitHub Pages, аккаунты, история и Realtime — Supabase.

Адрес: https://romentiy2012-droid.github.io/mayak-messenger/

## Первый запуск

1. В Supabase: Authentication → Sign In / Providers → Email — включён, **Confirm email выключен**. Участники входят по имени: приложение само превращает имя в технический адрес `u_…@mayak.app`, писем на него не приходит, поэтому подтверждение почты пройти нельзя.
2. Выполнить по порядку миграции из `supabase/migrations/` и развернуть функции `push` и `reset` (обе с выключенной проверкой JWT).
3. Выполнить `supabase/owner-invite.sql` в SQL Editor. Полученный одноразовый код хранить приватно, не добавлять в репозиторий.
4. В приложении выбрать «Регистрация», указать имя, пароль и код владельца.
5. Владелец создаёт приглашение кнопкой «Пригласить». На втором телефоне участник регистрируется по ссылке.

Новый гостевой код отменяет предыдущий неиспользованный код; действует 7 дней, используется один раз. Приглашённые видят всю историю общего чата.

## Вход и забытый пароль

- Для входа нужно имя, указанное при регистрации, и пароль. Имя в чате можно поменять («Участники и ваше имя») — для входа остаётся прежнее. Аккаунт, созданный раньше по настоящей почте, входит по этой почте.
- Участник забыл пароль: владелец открывает «Участники, имя и пароли» → «Сбросить пароль» и отправляет участнику ссылку. Она одноразовая, действует сутки, новая отменяет предыдущую. Участник открывает её, задаёт новый пароль и сразу входит; приложение показывает имя для входа.
- Владелец забыл свой пароль: Supabase → Authentication → Users → нужный пользователь → сменить пароль.
- Как устроено: код из ссылки хранится в базе только в виде хэша (миграция `…0004_reliability.sql`), пароль меняет функция `supabase/functions/reset` через служебный API авторизации.

## Push-уведомления

Web Push: приложение подписывает устройство, триггер базы вызывает Edge Function `push`, она шлёт уведомление всем, кроме автора. Разовая настройка в Supabase:

1. Выполнить `supabase/migrations/202611160002_push.sql` (в ней адрес функции проекта — при смене проекта поправить).
2. Развернуть Edge Function `push` из `supabase/functions/push/index.ts` с выключенной проверкой JWT («Verify JWT with legacy secret»).
3. Приватный VAPID-ключ положить в Vault: `select vault.create_secret('<ключ>','mayak_vapid_private_key');` (или в секрет функции `VAPID_PRIVATE_KEY`). В репозиторий не добавлять.

Надёжность: сообщение считается отправленным только после ответа push-сервисов. При временном сбое функция повторяет отправку сама (три попытки), а база раз в минуту (pg_cron, задача `mayak-push-retry`) заново вызывает функцию для недоставленного — до шести раз в течение 15 минут и только по тем устройствам, которым не дошло. Нужна миграция `…0004_reliability.sql`.

На устройстве: кнопка «Включить уведомления» в чате или в меню «⋯». iPhone — только из приложения, добавленного на экран Домой (iOS 16.4+). Android — Chrome/Яндекс/Firefox, лучше установленное приложение. Если чат открыт на экране, уведомление не показывается.

Смена VAPID-ключей: новый публичный — в `config.js` и `supabase/functions/push/index.ts`, приватный — в секрет; устройства переподпишутся при следующем открытии.

## Возможности чата (2.2)

Тёмная тема, ответы, реакции, изменение и удаление своих сообщений, «прочитано», «печатает…», счётчик непрочитанных, звук нового сообщения. Нужна миграция `supabase/migrations/202611160003_features.sql` (после `…0002_push.sql`) и актуальная версия функции `push`.

## Меню сообщения и реакции (2.15)

Удержание сообщения открывает меню рядом с ним: выбранное сообщение остаётся чётким на размытом фоне, сверху — быстрые реакции, снизу — «Ответить» и доступные действия. Стрелка раскрывает полную палитру над сообщением; можно выбрать реакцию или ввести свой смайл. Повторный выбор своей реакции снимает её. Своё текстовое сообщение можно изменить, удаление сохраняет прежние права и отдельное подтверждение.

На компьютере меню открывается правой кнопкой мыши или кнопкой «⋯». Escape и нажатие на фон закрывают меню; клавиатурный фокус остаётся внутри окна и возвращается после закрытия. Смахивание влево начинает ответ, короткое нажатие на медиа воспроизводит его. Удержание play-кнопки голосового или кружочка открывает меню без запуска звука. Выбранное сообщение в меню — пассивный снимок, без второго плеера и дополнительной загрузки. Длинный текст сокращается в предпросмотре; меню учитывает видимую область при открытой клавиатуре.

Проверки: `npm run test:message-menu-ui` и `npm run test:video-actions-ui` — синтетическая переписка, реакции, жесты, фокус, три темы, узкие экраны и модель visualViewport с клавиатурой. Физический iPhone проверяется отдельно. `js/message-menu.js` должен входить в `SHELL`.

## Фото и голосовые (2.7)

Файлы лежат в закрытом бакете `mayak` в Supabase Storage: читают участники чата, загружает каждый в свою папку, стирает автор или владелец. Фото перед отправкой уменьшается до 1600 точек (JPEG), голосовое записывается до 5 минут. Сообщение с вложением создаёт RPC `mayak_attach`; удаление сообщения стирает и файл. Нужна миграция `supabase/migrations/202611160006_media.sql` — применять её **до** выкладки приложения. Бесплатный Supabase даёт 1 ГБ хранилища.

В версии 2.14.1 плеер сверяет конец голосового с декодированной дорожкой. Длинный хвост почти цифровой тишины (от трёх секунд) пропускается, с запасом 0,25 секунды после последнего звука. Паузы внутри сообщения и тихая речь сохраняются; исходный файл не меняется. Проверка выполняется локально при первом воспроизведении, без повторной загрузки. Если браузер не может декодировать формат для проверки, остаётся обычное воспроизведение до `ended`. Длительность новых записей также уточняется по дорожке, а не только по часам. Проверки: `npm run test:voice` и `npm run test:voice-ui` (синтетические WAV/AAC/MP4 и настоящий Chrome; физический iPhone проверяется отдельно).

Версия 2.14.2 исправляет отдельный дефект Opus в MP4: MediaRecorder может записать скачок времени в длительность первого пакета, из-за чего короткая запись отображается как гораздо более длинная. Перед воспроизведением такого файла локально выравниваются временные метки по длительности Opus-пакетов; звук не перекодируется, облачный оригинал остаётся прежним. Это работает и с ранее сохранёнными в кэше файлами и не зависит от доступности Web Audio декодера. Распознаётся только узкая структура одного Opus-трека с большим начальным скачком; внутренние разрывы, обычные AAC/Opus и незнакомые контейнеры не переписываются. Новые записи предпочитают явно указанный AAC-LC, когда он поддерживается, и также проходят проверку таймлайна перед отправкой. Регрессионная Opus/MP4 fixture создаётся из синтетического тона, без пользовательских записей. Модуль `js/voice-mp4.js` должен входить в `SHELL`.

## Личные чаты (2.8)

Кроме общего чата, с каждым участником есть личный — его видят только двое (это проверяет база, правило `messages_read`). У личного сообщения заполнена пара `peer_a`/`peer_b`; «прочитано» и «печатает» для личных чатов — в таблице `mayak_reads`. Отправка — `mayak_post_to` / `mayak_attach_to` (пустой адресат = общий чат). Админские права на удаление действуют только в общем чате. Нужна миграция `supabase/migrations/202611160007_direct.sql` — применять **до** выкладки приложения.

## Аватарки (2.10)

Откройте свой профиль: аватарка у поля ввода на телефоне, имя внизу боковой панели на компьютере или меню «⋯» → «Профиль и участники». Можно поставить своё фото, выбрать один из 24 значков (животные, транспорт, сердце, ключ и другие) или оставить буквы. Нажмите «Сохранить профиль», чтобы применить выбор; закрытие окна отменяет изменения.

Фото обрезается по центру в квадрат 384 × 384, уменьшается и сохраняется как JPEG без исходных метаданных. Перед сохранением виден предпросмотр. Аватарки одинаковы на всех устройствах и обновляются у участников без перезагрузки. При недоступном фото показываются буквы.

Нужна миграция `supabase/migrations/20261117130822_avatars.sql` **до** публикации клиента. Фото находятся в отдельном закрытом бакете `mayak-avatars` (только JPEG, до 512 КБ); читают их участники чата, каждый меняет только свою аватарку. Прежнее фото после успешной замены удаляется приложением. На устройстве фото аватарок остаются только в памяти текущего входа.

Проверки: `npm test` — база и права, `npm run test:avatars-ui` — отдельный браузерный сценарий с подставным облаком (нужен установленный Chrome).

## Видеокружочки (2.11)

Кнопка камеры у поля ввода открывает запись с предпросмотром: сначала разрешите камеру и микрофон, затем нажмите «Начать запись». Можно записать до минуты, переснять или отменить; отправка происходит только по кнопке «Отправить». Камера и микрофон выключаются после записи и при закрытии окна. Если браузер не поддерживает запись, кнопка скрыта.

Исходный MP4 или WebM обрабатывает отдельный `video-worker`: итог — квадратный MP4 480 × 480, H.264 Baseline / AAC-LC, yuv420p, с быстрым началом воспроизведения. В ленте он отображается кругом, по нажатию включаются видео и звук. Совместимость формата проверена локально и при облачной сборке обработчика; проверка настоящих iPhone/Android ещё требуется.

Внедрение: миграция `supabase/migrations/20261117161458_video_notes.sql`, Edge Function `video` с собственной проверкой токена, обработчик из `video-worker/` и его закрытая конфигурация в БД. Подробности — `video-worker/README.md`. В рабочем проекте обработчик развёрнут и `MAYAK_CONFIG.videoEnabled` включён. При самостоятельном развёртывании держите флаг выключенным до настройки обработчика.

Оба бакета закрытые: исходник до 16 МБ в `mayak-video-source`, результат до 8 МБ в `mayak-video`. Готовое личное видео читают только участники его переписки. Клиент не может выдавать произвольный файл за обработанный результат. Повтор после потери ответа продолжает то же задание; сообщение появляется один раз. После успешной отправки исходник удаляется. Отмена и повторные ошибки могут оставлять неиспользованные файлы; плановая очистка ещё не настроена.

Проверки: `npm test`, `npm run test:video-worker`, `npm run test:video-ui`. Браузерный сценарий использует искусственную камеру, закрытый локальный сервер и подставное облако; реальные сообщения не создаёт.

Исправление 2.11.1: служебные API-запросы Edge Function используют собственный `apikey`; новые непрозрачные ключи `sb_secret_…` не передаются как JWT в `Authorization`. Пользовательский JWT остаётся в запросах от имени участника. Поддерживаются стандартные JSON-наборы `SUPABASE_SECRET_KEYS` / `SUPABASE_PUBLISHABLE_KEYS` и прежние переменные окружения. Ошибка обработки сохраняет запись для повтора и не выдаётся за отсутствие сети, если сервер ответил. Серверное исправление работает и для уже открытого клиента 2.11.0: достаточно повторить отправку сохранённой записи.

Исправление 2.11.2: записи с полным диапазоном цвета приводятся к limited range при масштабировании и кодировании. Прежняя проверка отклоняла такой результат как `yuvj420p`; теперь на том же облачном FFmpeg воспроизводится регрессия и проверяется исправление, включая декодирование результата. Тесты включают обычные WebM/MP4 и full-range MP4. Диапазон limited может не иметь отдельного тега FFprobe; обязательны `yuv420p` и отсутствие `pc`.

С версии 2.11.3 на телефоне удерживайте кружочек, чтобы открыть реакции и «Ответить», или нажмите «⋯» рядом с ним. Смахивание кружочка влево начинает ответ. Короткое нажатие включает или приостанавливает видео; после жеста воспроизведение случайно не включается. На компьютере меню также открывается правой кнопкой мыши и кнопкой «⋯».

С версии 2.17.0 окно записи сохраняет размеры и положение при тапах, загрузке камеры, записи и просмотре результата. Круглый предпросмотр не зависит от исходного разрешения камеры, места кнопок зарезервированы. Поворот устройства меняет раскладку под новую ориентацию. Фон внутри окна — тот же морской узор: светлый в светлой теме, тёмный в тёмной, приглушённый в терминальной.

Кнопка со значком камеры справа от заголовка переключает фронтальную и основную камеры **до начала записи**. Старая камера и микрофон освобождаются перед запросом новой; если переключение недоступно, приложение возвращается к прежней камере. Зеркальным остаётся только живой предпросмотр фронтальной камеры. Во время записи и просмотра готового ролика переключение недоступно; «Переснять» сохраняет выбранную камеру. Закрытие окна останавливает все полученные потоки, включая поздний ответ на запрос камеры. Запись становится доступна после готовности предпросмотра.

Проверки окна: `npm run test:video-recorder-ui` — реальные touch-события Chrome и тестовые MediaStream с моделируемыми фронтальной/основной камерами, стабильная геометрия, темы, переключение, отказ второй камеры и отмена незавершённого запроса. `npm run test:video-ui` проверяет настоящую запись тестовой камерой, конвертацию FFmpeg и отправку в подставное облако. Физический iPhone проверяется отдельно.

Неотправленный кружочек привязан к исходному чату, который явно указан под записью. Смена чата и отправка при несовпадении адресата блокируются; файл, nonce и задание автоматически не переадресуются. При повторе сервер сначала резервирует новую попытку и только затем отвечает, чтобы клиент не принял старую ошибку за результат новой обработки. Для отправки видео нужен клиент 2.11.2 с явным контекстом чата; старому клиенту предлагается обновиться. Если кружочек был записан для общего чата, для личного сообщения уберите вложение и запишите новое в личном чате.

## Хранилище и лимиты (2.12)

Владелец открывает меню «⋯» → «Хранилище и лимиты». Окно показывает текущий размер всех файлов проекта, запас до проверенного лимита Free 1 ГБ, разбивку по типам и время снимка. Лимит относится ко всей организации; здесь считается объём файлов Маяка. Это не среднемесячное использование квоты GB-Hrs. Если размер части объектов неизвестен, остаток не выдаётся за точный. Условия Free подтверждены 18.11.2026; при смене тарифа обновите серверные значения и дату проверки в `storage-admin`.

Месячный трафик не вычисляется из размера файлов или количества запросов. Доступный официальный API Supabase не предоставляет достоверный накопленный egress и границы расчётного периода: карточка честно показывает отсутствие данных и ссылку на Usage организации. Отдельно указаны условия Free: 5 ГБ uncached и 5 ГБ cached. Удаление файлов не возвращает израсходованный трафик. Хранение учитывается в среднем за период, поэтому очистка может не сразу снять ограничение квоты.

Список содержит только тип, дату, размер и непрозрачный ID; содержимое, подписи и технические пути личных вложений в окно не передаются. Можно выбрать до 20 файлов, проверить объём и подтвердить безвозвратное удаление из облака. Текст, подписи, реакции и цитаты остаются; вложение заменяется отметкой об удалении. Используемые аватарки, обрабатываемые видео и недавние исходники/неиспользуемые загрузки защищены. Первые 24 часа новые файлы без сообщения не удаляются, чтобы сохранить незавершённую отправку.

Операция имеет постоянный nonce и фиксированный набор версий объектов. Сервер сначала проверяет весь выбор и резервирует его, затем удаляет физические объекты через Storage API и подтверждает их отсутствие. При частичном сбое освобождённое место не вычитается предположительно; операция восстанавливается после закрытия окна и продолжается тем же набором без повторного учёта уже удалённого. Очистка метаданных Storage через SQL не используется. Защита новых ссылок на выбранные файлы действует на уровне БД. Обычные участники не могут вызвать служебные функции даже при ручном запросе.

Внедрение: миграция `supabase/migrations/20261118060239_storage_admin.sql`, затем функция `storage-admin` с собственной проверкой пользовательского JWT и текущей роли владельца. Не передавайте secret/service keys в браузер. Миграция также сужает чтение/удаление личных фото и голосовых в Storage до участников соответствующего чата; администраторская очистка выполняется отдельной серверной операцией. Автоматического удаления старых файлов нет.

Проверки: `npm test`, `npm run test:storage-ui`, `npm run test:video-actions-ui`. Они используют синтетические данные; настоящие файлы участников тестами не удаляются.

Источники: [Storage size](https://supabase.com/docs/guides/platform/manage-your-usage/storage-size), [Egress](https://supabase.com/docs/guides/platform/manage-your-usage/egress), [удаление объектов](https://supabase.com/docs/guides/storage/management/delete-objects), [Management API](https://supabase.com/docs/reference/api/introduction).

## Опросы (2.13)

Кнопка «＋» рядом с полем сообщения открывает «Фото» и «Опрос». Опрос создаёт любой участник в общем или своём личном чате: вопрос до 300 символов, 2–10 разных вариантов до 100 символов, один или несколько ответов. По умолчанию опрос анонимный для участников; в открытом режиме кнопка «Кто голосовал» показывает имена и выбор. Вопрос, варианты и режим после отправки фиксируются. Обычный текстовый черновик при создании опроса сохраняется.

Один вариант выбирается нажатием; при нескольких вариантах нужно отметить ответы и нажать «Голосовать». До завершения можно изменить выбор или отменить голос. Проценты считаются от числа проголосовавших, поэтому при нескольких ответах сумма может превышать 100%. Автор завершает свой опрос, администратор — также любой опрос общего чата; дополнительных прав в чужой личной переписке у него нет. Опрос поддерживает ответы и реакции как остальные сообщения.

Миграция `supabase/migrations/20261118103108_polls.sql` добавляет закрытые таблицы вопросов, бюллетеней и применённых запросов. В публичном сообщении и Realtime есть только вопрос, настройки и агрегаты; чужие анонимные бюллетени не доступны через клиентские запросы, включая автора опроса. Это анонимность для участников приложения, не гарантия недоступности оператору базы. Собственный выбор выдаётся отдельным RPC с проверкой актуального участника и чата. Сервер сериализует голосование и закрытие по сообщению; повторы с тем же nonce не дублируют опрос и не откатывают более новый выбор. После удаления сообщения голосование недоступно. Голоса удалённого участника сохраняются в итогах, в открытом списке он обозначается как удалённый.

Незавершённая отправка опроса и неподтверждённый голос сохраняют исходный запрос на устройстве для безопасного повтора после закрытия или перезагрузки. Невыбранный множественный черновик не сбрасывается при обновлении итогов. Проверки: `npm test` и `npm run test:polls-ui`; браузерный сценарий использует синтетическое облако и не создаёт сообщения в рабочем чате. На самостоятельно развёрнутом проекте сначала примените миграцию, затем публикуйте клиент.

В версии 2.13.1 окна подстраиваются под видимую область над экранной клавиатурой: выбранное поле прокручивается внутри окна, в том числе при переходе между вариантами опроса и повороте телефона. Размер и смещение берутся из VisualViewport; один только `vh` не учитывает клавиатуру iPhone. Проверка `npm run test:polls-ui` моделирует уменьшение и смещение видимой области без изменения размера страницы, переход по полям, ручную прокрутку до кнопки отправки и восстановление высоты. Это браузерная симуляция, не проверка физического iPhone.

## Автоматическое обновление (2.14)

Маяк проверяет новую версию после загрузки, при возвращении в приложение/восстановлении интернета и раз в минуту, пока открыт. Сначала Service Worker полностью загружает оболочку в кэш; после его активации клиент сверяет версию через MessageChannel. Первая установка не вызывает перезагрузку. Если новая оболочка не установилась, текущая продолжает работать.

Экран автоматически перезагружается после трёх секунд без действий, когда нет фокуса в поле, открытого окна, редактирования, выбранного файла, подготовки/записи медиа, воспроизведения и незавершённой записи в облако. Обновление не применяется в скрытом приложении, без интернета или без связи с облаком у вошедшего участника. Если действие ещё идёт, появляется короткая полоса: обновление ждёт его завершения. Текстовый черновик с ответом/nonce сохраняется обычным механизмом; текущий чат и доступный якорь прокрутки восстанавливаются в той же вкладке. Сохранённый вход остаётся в Auth, пароль не копируется в новый механизм. При ошибке сохранения черновика или sessionStorage принудительной перезагрузки нет. В одной вкладке допускается только одна автоматическая попытка на целевую версию, чтобы старый ответ сервера не запустил цикл.

Проверка `npm run test:updates-ui` использует настоящий Service Worker в Chrome, несколько синтетических выпусков и облако-заглушку. Реальные аккаунты и сообщения не используются. Новый модуль `js/updates.js` обязательно входит в `SHELL` в `sw.js`. При выпуске синхронно меняйте APP_VERSION, VERSION в worker, package/lock, подпись интерфейса и «О Маяке».

Это не удалённое управление телефоном: закрытые/offline PWA нельзя гарантированно обновить одновременно. У версий до2.14 ещё нет клиентского механизма безопасной перезагрузки, поэтому для первоначального перехода на2.14 может понадобиться обычный запуск/один перезапуск; дальнейшие выпуски применяются автоматически при безопасных условиях. Worker не вызывает принудительный navigate старых окон: они не умеют сообщать о незавершённой записи и могли бы потерять вложение.

Официальные источники: [обновление PWA](https://web.dev/learn/pwa/update), [registration.update](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/update), [controllerchange](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/controllerchange_event).
## Виды оформления

Два вида, переключаются в меню «⋯» → «Оформление»: «терминал» (зелёный экран, по умолчанию) и «обычное» (со светлой и тёмной темой). Выбор хранится на устройстве. `theme.js` ставит на `<html>` атрибуты `data-skin` и `data-theme`; «терминал» — отдельный блок в конце `style.css`, который накладывается поверх обычных стилей. Устройство экрана у обоих видов одно. Изображения и названия сторонних игр и систем не используются.

С версии 2.16.0 за перепиской размещён выбранный Кэпом морской узор: маяки, кораблики, якоря, компасы и волны. **Постоянное правило оформления: в светлой теме фон светлый, в тёмной — тёмный.** Правило действует и при выборе «как в телефоне»; в терминальном оформлении фон также тёмный и более приглушённый. При будущих изменениях не оставлять светлую картинку в тёмной теме.

Исходный узор хранится в `assets/chat-nautical.png`. Тёмное отображение создаётся CSS на отдельном слое, поэтому рисунок остаётся тем же, а цвета сообщений, фото и кнопок не меняются. Фон занимает только область истории, остаётся неподвижным при прокрутке и масштабируется без повторяющихся стыков. Изображение входит в `SHELL` для работы без сети; при замене файла нужно обновить версию приложения и кэша.

## Разработка

`npm ci`, `npm run build`, `npm test`.

Код приложения — модули без сборки: `app.js` (точка входа) и `js/`: `core` (состояние, помощники), `session` (вход, получение сообщений), `messages` (лента, обновляется по частям), `composer` (поле ввода, черновики), `actions` (меню сообщения, жесты), `dialogs` (окна), `push`, `viewport`, `sound`. `cloud.js` — всё общение с Supabase. Новый файл нужно добавить в список `SHELL` в `sw.js`, иначе он не попадёт в офлайн-кэш. Недописанное сообщение хранится на устройстве и переживает перезапуск.

`config.js` содержит только URL и публичный ключ. Секретные ключи здесь запрещены. Миграция создаёт RLS и ограниченные функции записи; таблица приглашений закрыта для прямого чтения. Тест проверяет права владельца, гостя, постороннего, одноразовые приглашения и идемпотентность сообщений.

## Ограничения

HTTPS есть, сквозного шифрования нет. Push-уведомления требуют разовой настройки (см. выше) и разрешения на каждом устройстве. Бесплатный Supabase может приостанавливать неактивные проекты.
